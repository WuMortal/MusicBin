# 音乐源插件化实现方案（MusicFree 插件协议）

## Context

用户希望像 LX Music / MusicFree 一样支持**可配置音乐源**：现有 gequbao（歌曲宝）源保留为内置源，同时支持安装社区 MusicFree 插件（用户已提供插件市场 `https://musicfreepluginshub.2020818.xyz/plugins.json`），安装方式=市场浏览+手动 URL 两种；插件源下载的歌曲要与内置源体验一致（ID3v2.3 内嵌封面/歌词 + UTF-8 BOM `.lrc`）。

现状：所有源逻辑硬编码在 Rust `music.rs`（gequbao），前端 `musicApi.ts` 只是 7 个 invoke 薄封装。约束：`useHttpsScheme:true` 使 webview fetch 受 CORS 限制 → 插件网络必须经 Rust reqwest 代理；`csp:null` 允许脚本注入。MusicFree 插件=单 JS 文件 CommonJS 模块：`module.exports = { platform, version, userVariables?, async search(keyword,page,type)→{isEnd,data}, getMediaSource(item,quality)→{url,headers?}, getMusicInfo→{title,artist,artwork}, getLyric→{rawLrc} }`，运行时需宿主注入 `require`（cheerio/axios/crypto-js 等）、`env`、网络能力。

## 总体架构

```
SearchPage → musicApi(兼容签名) → 源路由(lib/source) ─内置→ Rust music.rs 原命令
                                      └插件→ PluginHost(iframe 沙箱) ←postMessage RPC→ sandbox.html
                                                └网络请求→ invoke plugin_fetch(Rust reqwest)
下载: 插件源收集 url/meta/lrc → invoke plugin_download_track(封面下载+ID3+.lrc 与内置共用逻辑)
```

## 实施步骤（按顺序）

### 1. Rust 通用命令 — 新建 `src-tauri/src/plugin.rs`，`lib.rs` 注册

- 重构 `music.rs`：从 `download_track`(:337) 抽出 `download_stream(app,cli,url,full_path)`（含 256KB 进度 emit、headers 可选参数）；从 `download_track_with_meta` 尾段(:583-622) 抽出 `finish_download(cli,path,file_base,title,author,cover_url,lrc)`（封面下载+embed_id3+BOM .lrc），`download_track_with_meta` 改为调这两个内部函数（行为不变，内置 kuwo.cn 白名单保留在 `download_track` 命令层）。
- 新命令（复用 `client()`）：
  - `fetch_text(url: String) -> Result<String,String>`：拉市场 plugins.json / 插件 js 全文（安装时全文入库，离线可用）。
  - `plugin_fetch(url, method?, headers?, body?, binary?) -> FetchResult{status,headers,body}`：插件网络代理，body 为 text 或 base64；**必须支持透传插件返回的 headers**（Referer/UA/Cookie），否则大量音源 403。
  - `plugin_download_track(app, url, file_name, dir, title, author, cover_url, lrc, headers?) -> DownloadResult`：无域名白名单；调 `download_stream`+`finish_download`，进度事件与内置一致。

### 2. Vite 多入口 + 沙箱页

- `vite.config.ts`：`build.rollupOptions.input = { main: index.html, sandbox: sandbox.html }`（dev 下 Vite 自动 serve `/sandbox.html`）。
- 根目录新建 `sandbox.html`（最小骨架）+ `src/sandbox/main.ts`：
  - RPC 服务端：监听 message，`new Function('module','exports','require','env','console', js)` 执行插件（每次 init 一个新 Function 域）；校验 `platform`/`version` 后回 `ready`（带 userVariables 声明）。
  - shim：`fetch`→postMessage 代理（用 `new Response(...)` 构造真实 Response）；`require(name)`→动态 `import()`（cheerio 浏览器版/crypto-js/dayjs/qs/he，Vite 自动拆 chunk，勿进主 bundle）；`require('axios')`→迷你 axios（get/post/config、`res.status/headers/data`、4xx/5xx reject 语义——插件普遍靠 catch 处理）；console 转发宿主。
  - method 白名单：`search/getMediaSource/getMusicInfo/getLyric`；插件 throw → 回 error（message 截断 500 字）。
  - 消息协议：`{v:1,ch:'mvsp',instanceId,msgId,kind}`；kind= init/call/fetch-res（宿主→沙箱），ready/result/error/fetch/log（沙箱→宿主）。

### 3. 宿主 bridge — 新建 `src/lib/sandbox/PluginHost.ts`

```ts
class PluginHost {
  constructor(code, js, env)
  load(): Promise<void>   // <iframe sandbox="allow-scripts" src="…/sandbox.html?instance=xx" style="display:none">；src 按 DEV 分支 http://localhost:1421 / https://tauri.localhost
  call<T>(method, args, timeoutMs=15000): Promise<T>  // 超时 dispose+reject
  dispose(): void
}
```

安全要点：sandbox **只加 `allow-scripts`**（绝不加 `allow-same-origin`，防插件经 parent 摸到 Tauri internals）；opaque origin 下 `e.origin==='null'`，校验靠 `e.source===iframe.contentWindow` + instanceId 匹配；postMessage `targetOrigin:'*'`。宿主监听 `fetch` kind→`invoke('plugin_fetch')` 转发。每个插件一个 iframe、懒创建后保留（track.source 可能≠激活源，切源后仍要调其 getMediaSource）。

### 4. 源抽象与路由 — 新建 `src/lib/source/`

- `types.ts`：`MusicSource { code,name,builtIn, search(kw), guess?(kw), getPlayUrl(track), getTrackMeta?(track), download(track,dir) }`。
- `builtin.ts`：包装现有 7 invoke（download 走 `download_track_with_meta`）。
- `plugin.ts`：`PluginSource`——search 映射 `Track{id,title,author:artist,source:code}` 并缓存原始 musicItem（Map，getMediaSource 需完整 item）；getPlayUrl=`call('getMediaSource',{musicItem,quality:'standard'})`，**透传返回的 headers**；getTrackMeta=getMusicInfo+getLyric 合并；download=三者齐后 `invoke('plugin_download_track')`，fileName=`${title} - ${author}`。
- `index.ts`：settings keys `mv.music.plugins`（[{code,name,version,url,js,userVariables?}]，单插件上限 1MB 拒装、QuotaExceeded catch+toast）、`mv.music.source`（激活 code 默认 'gequbao'）、`mv.music.env.<code>`（userVariables 值）；`resolveSource(code)` 实例缓存；导出兼容签名 `searchMusic/guessMusics(永远内置)/getPlayUrl(track)/getTrackMeta(track)/downloadTrack(track,dir)`；`musicApi.ts` 改 re-export 保持旧 import 路径。
- `src/types.ts`：PlayRecord 加 `source: string`。

### 5. 设置页 UI — `SettingsPage.vue` + 新组件 `src/components/MarketDialog.vue`

「音乐源」sec：
- 激活源：`.seg` 分段控件（内置 + 已装插件），沿用应用风格。
- 插件行：名/版本 + 删除（confirm danger）+ 配置（userVariables 有声明时，玻璃风格小弹窗）。
- 「添加插件」：URL 输入+安装按钮 → `fetch_text` → 临时 PluginHost 校验 → 存 localStorage → toast。
- 「插件市场」：拉 hub plugins.json（兼容两种格式：`url||href`、`name||code` 字段容忍）→ 1080×720/90vh 玻璃大弹窗列表 → 每项安装按钮（重复 code confirm 覆盖）。市场地址可编辑（预填用户给的 URL）。

用户偏好：纯色按钮小圆角紧凑、弹框风格统一、参数不一行一个。

### 6. SearchPage 收尾 — `src/pages/SearchPage.vue`

- :180-183 改 `getPlayUrl(track)`、`getTrackMeta(track)`（传整个 track）。
- :272 改 `downloadTrack(track, dir)`（router 分发，SearchPage 不再关心源类型）。
- `addPlayRecord` 传 `source: track.source`；`playRecent`/`toggleCurrent` 用 `r.source || 'gequbao'` 路由。

## 验证

1. 每步 `npm run typecheck` + `cargo check`；Rust 改动需重启 `npm run tauri dev`。
2. 回归：gequbao 搜索/试听/下载（ID3 封面歌词 + .lrc BOM）不变。
3. 手测：市场拉取列表→安装一个音源插件→激活→搜索试听（devtools 确认走 plugin_fetch 无 CORS）→下载（ID3/.lrc 与内置一致）。
4. 异常路径：坏 URL 安装报错；播放记录重放缺源时降级/报错；call 超时 15s 销毁重建；userVariables 配置注入。
